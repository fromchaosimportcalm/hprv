## Raid-frame flags are role assignments, and a stale one silently reassigns the raid
Date: 2026-08-15
Tags: playerbots,groups,flags,maintank,assistant,rule-1,blacktemple,hprv

Context: `docs/raid-night.md` told you to leave the raid frames alone — "**No raid-frame flags.** You are the only body `IsTank()` accepts, so `GetMainTankGuid()` resolves to you on its own. Do not flag anyone." That was written for the mode where the human tanks, and it was true only because no member happened to carry a flag. Measured on the box 2026-08-15, mid-Black-Temple, reading `acore_characters.group_member.memberFlags` for the live 27-member raid: `Ararin` = **2** (`MEMBER_FLAG_MAINTANK`), `Izri` = **1** (`MEMBER_FLAG_ASSISTANT`), `Nathos` and `Lomul` = **4** (`MEMBER_FLAG_MAINASSIST`), everyone else `0`. Nobody set those deliberately; they are residue from earlier nights, and they survive logout, server restart and `KeepAltsInGroup` regrouping because they live in the group row, not in memory.

`GetMainTankGuid()` (`PlayerbotAI.cpp:2378`) scans the member slots for `MEMBER_FLAG_MAINTANK` and returns that guid **without ever calling `IsTank()`**. Only when no member carries the flag does it fall back to the first alive `IsTank()` body. So the module's main tank was `Ararin` — converted `-tank` under rule 1, running DPS strategies, holding no taunt, and sitting at 476 defence skill, i.e. crittable — while `Bullwark`, prot-specced and hand-itemized at 534, was not the main tank at all. Everything keyed on `IsMainTank()` followed the flag with him: the Illidari Council's Gathios assignment (`BTStrategy.cpp:124`, trigger `illidari council gathios engaged by main tank`), and, everywhere in the game rather than only in raids, the generic hunter Misdirection — `GenericHunterStrategy.cpp:68` wires `low tank threat` to `misdirection on main tank`, and `BuffOnMainTankAction::GetTargetValue()` (`GenericSpellActions.cpp:667`) resolves that through `FindMainTankPlayer::Check → IsMainTank()` (`PartyMemberValue.cpp:155`). Every hunter Misdirection in the raid was being handed to the wrong body.

The assistant flag is not decoration either — it is an ordering key. `IsAssistTankOfIndex` (`PlayerbotAI.cpp:2500`), `IsAssistHealOfIndex` (`:1938`) and their ranged/melee siblings all compute an index in which **assistants sort ahead of non-assistants**, group order breaking ties within each band. And `GetZerevorMageTank` (`Ai/Raid/BT/BTHelpers.cpp:138`) returns the first *assistant* mage it finds — checking neither bot-ness nor anything else — before falling back to the first bot mage. That is how the human, carrying a stale assistant flag, silently became the Council's designated Zerevor tank, with a healer being positioned on her, without a word of notification.

Decision: **The raid-frame flags are the module's role-assignment surface. Set them deliberately, and audit them before any scripted encounter.** Concretely: whenever a bot main-tanks, put `MEMBER_FLAG_MAINTANK` on that bot — do not rely on the `IsTank()` fallback; use the assistant flag to pin the per-role indices you actually want, rather than accepting group join order; and read the flags out of the database before a serious night rather than trusting the raid frames to look empty. The audit is one query:

```sql
SELECT c.name, c.class, c.online, gm.memberFlags, gm.subgroup
  FROM acore_characters.group_member gm
  JOIN acore_characters.characters c ON c.guid = gm.memberGuid
 ORDER BY gm.subgroup, gm.memberGuid;
```

`1` = assistant, `2` = main tank, `4` = main assist (`Group.h:73-75`). Only the first two mean anything to the module; `MEMBER_FLAG_MAINASSIST` is read nowhere in it, so `Nathos` and `Lomul` carrying it had no effect at all.

**This reverses "do not flag anyone" in `docs/raid-night.md`.** That advice survives in exactly one case — the human tanks *and* no member carries any flag — and it gave no way to detect the second half of that condition failing.

Permissions matter and are split three ways in `GroupHandler.cpp`: raid target icons need leader **or** assistant (`:629`); main tank / main assist assignment needs leader **or** assistant (`:727`); promoting somebody to assistant is **leader only** (`:713`). A bot holding raid lead is the normal state, not an anomaly — `KeepAltsInGroup` restores whatever group existed, and a group formed while you played `Bullwark` has `Bullwark` as leader forever after. Take it back with the module's own command, `/w Bullwark give leader` (`GiveLeaderAction`, which requires an active player master and the bot currently holding lead), or with `.group leader <name>` as a GM fallback.

Reasoning: The failure mode is the one this project keeps meeting — a setting that is silently wrong presents as an unrelated fault. A stale `MEMBER_FLAG_MAINTANK` does not error, does not log, and does not show up in any `co` audit; it simply hands every main-tank-keyed mechanic in the module to a body that was deliberately stripped of tank strategies. It is also invisible from inside the game unless you happen to open the raid frames and look for a shield icon nobody remembers setting. Rule 1's conversion whisper makes this strictly worse rather than better: the more thoroughly the plate bots are converted, the more certain it is that a flagged one cannot do the job the flag assigns it. Reading the flags costs one query and closes the whole class of fault.

Setting flags deliberately also turns three previously uncontrollable assignments into chosen ones. Group join order decides assist-tank and assist-heal indices otherwise, and join order changes every time a body is summoned or a bot is re-added, so the same raid produces different assignments on different nights for no visible reason. Promoting the two bodies you want as assist tank 0 and 1, and the healer you want as assist heal 0, makes the assignment stable across sessions and reviewable in one query.

Alternatives: Clear every flag and keep relying on the fallback — attractive because it needs no upkeep, but it only works while exactly one `IsTank()` body exists, which ADR `0004` deliberately breaks for the Illidari Council, and it leaves the per-role indices at the mercy of join order. Set the flags in the client and trust memory — that is what produced the stale `MEMBER_FLAG_MAINTANK` on `Ararin` in the first place. Patch the module so `GetMainTankGuid()` validates the flagged body with `IsTank()` before returning it — the right fix upstream, and a genuine candidate for the local patch series in `CLAUDE.md`'s open questions, but it is a relink and it would not have helped the assistant-flag half of this at all.
